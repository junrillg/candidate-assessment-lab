# Implementation contracts

All HTTP JSON uses camelCase, UUID IDs, ISO UTC times, ordinary 400/401/403/404/409 errors `{error: string}`. Authenticated same-origin cookies; unsafe HTTP requests require `X-CSRF-TOKEN` from GET /api/session. Exceptions never return provider responses or answer/audio contents. Modules map their endpoints and own their contexts. Module entities and DbContexts are internal; only public contracts and composition extension classes cross assemblies.

## Access (root agent)
GET /api/session => {authenticated, userId?, name?, role?, csrfToken, serverTime}. POST /api/login {email,password}; POST /api/logout. Policies `Candidate` and `Reviewer`. Claims NameIdentifier=user UUID, role Candidate/Reviewer. Seed identities: IDs 11111111-1111-1111-1111-111111111111 and 22222222-2222-2222-2222-222222222222 candidates; 33333333-3333-3333-3333-333333333333 reviewer. Passwords generated in ignored .local/credentials.json, consumed only during explicit seed.

## Assessments (agent)
GET /api/assignments => [{id,title,durationMinutes,attemptId?}]. POST /api/assignments/{id}/start {manualOnly:boolean} => AttemptView. GET /api/attempts/{id} => AttemptView. PUT /api/attempts/{id}/answers/{questionId} {revision:int,text:string,flagged:bool,recordingId:uuid?} => AnswerView. POST /api/attempts/{id}/recordings/{questionId}/{uploadId} with raw file body and Content-Type (audio/webm,audio/ogg,audio/mp4) => {id, questionId, size, contentType}; whole-file stable id. GET /api/attempts/{id}/recordings/{recordingId} authenticated private audio for owner or Reviewer. POST /api/attempts/{id}/submit => {receipt,submittedAt,attemptId}; repeated calls return same. DELETE /api/attempts/{id} owner/reviewer -> durable cleanup (202).
AttemptView {id,title,status,startedAt,deadline,serverTime,manualOnly,receipt?,questions:[{id,number,kind:"written"|"oral",title,prompt,rubric:[{id,label,anchors:string[]}]}],answers:[{questionId,revision,text,flagged,recordingId?}]}. Unanswered rows start revision 0. Status "active"|"submitted". Answers max 20000 chars. Frozen question/rubric snapshot at start; final snapshot at submit/expiry. For expiry close loop even if browser absent. Outbox publication receives stable processing intent ID, one per question, message IDs only.
Public read contract establish immediately and message Evaluation agent: `IAssessmentReader` methods get immutable question evidence by intent ID, list submitted attempts or other minimum review metadata, read private recording stream, existence/deletion check. Public record `ProcessingIntent` {Id,AttemptId,QuestionId,CorrelationId} ONLY metadata; public record evidence includes frozen prompt/rubric, answer, recording metadata and manualOnly. No EF types cross contract. Evaluation owns consumer dedupe durable jobs; consumer creates on repeated messages safely.

## Evaluation (agent)
GET /api/evaluation/{attemptId} owner or reviewer => {attemptId,status,questions:[{questionId,status,transcript?,suggestion?:{criteria:[{criterionId,score,evidence,rationale}],provider,model,promptVersion},review?:{criteria:[{criterionId,score}],feedback},error?}],publishedAt?,feedback?,total?,maximum?}. Candidate response NEVER exposes suggestions, transcripts/internal notes or un-published review; candidate only processing status and published feedback/scores. GET /api/reviews reviewer => [{attemptId,title,candidateId,status,submittedAt}]. PUT /api/reviews/{attemptId}/questions/{questionId} {criteria:[{criterionId,score}],feedback,internalNotes,revision:int} => saved review; require full valid criteria and score 0..5. POST /api/reviews/{attemptId}/publish {feedback,revision:int} => durable published record; immutable published review. POST /api/reviews/{attemptId}/questions/{questionId}/retry => retry terminal job. Audit human save, override, publish, retry.
Leases, fences, retries all persisted; consumer acknowledges only after durable commit. Metadata only Kafka. Transcription HTTP endpoint POST /transcribe raw audio returns {text}; implement provider adapter. Ollama /api/chat format JSON rubric criteria and retain evidence/version. Validate criteria identity, scores, evidence substring, reject bogus output. Failed jobs need review, never zero.

## Frontend (root)
Only root agent runs npm install/build/test. Raw API paths above. Local IndexedDB scoped per user/attempt/question; persist drafts immediately, one-second debounce; explicit conflict choices preserve local work. Record completed blobs before upload, stable upload ID. Flush acknowledged pending work before manual submit; explain server cutoff. Candidate prep, recording practice, persistent server-derived timer, workspace, review-before-submit, durable receipt, published feedback. Reviewer queue/detail using Evaluation and Assessments API.
